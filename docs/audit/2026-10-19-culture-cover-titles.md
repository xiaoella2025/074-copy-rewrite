# 传统文化封面标题去除重复套壳

## 核查结论

- 最近 14 个已有传统文化元信息产物：7 个标题含“门道”、4 个含“讲究”、3 个为其他表达。
- 从已提取 Story 1.24.5 的 `frontend/index.html` 确认实际入口 `assets/index-BL1mWGtO.js`，其传统文化元信息提示词确实含“从下列词库轮换选用”和“的秘密／哲学／讲究／密码／门道／规矩／玄机／来历”。074 的内置模板沿用同类规则，示例也大量是对象后接泛词。
- 原有任务保存了提示词快照，仅改内置 JSON 会让旧快照继续使用原规则。发现 15 份文化模板快照的元信息正文与本次记录的原版指纹完全匹配。没有读取正式 API Key，没有安装 Story。

## 实现

1. 只修改 `culture-knowledge.step1MetadataSystemPrompt`。标题从正文具体问题、概念区别、动作形制、事实反差或有依据的数字中提炼；优先 4–8 字，最多 10 字。
2. 移除泛后缀轮换词库，明确不能只是把“门道”换为“讲究／秘密／密码／玄机”。内部比较三个不同结构的候选，在同一次输出中只返回一条标题；不增加模型调用或对差标题自动付费重试。
3. 替换主标题示例及自检要求，强调具体问题、正文依据、不可编造或照搬无关例子的知识点。发布正文、标签、评论和其他赛道规则未改。
4. `culture_titles.metadata_prompt` 用已知原版元信息 SHA-256 识别旧快照，在发给模型前取当前内置标题规则；配置和已有产物不批量改写。用户修改过元信息正文或使用自定义模板 ID 时保留原规则。只改过其他字段、元信息仍为原版的文化模板会获得此次标题升级。
5. `assets/prompt_templates.provenance.json` 追加本次本地定制记录，保留原始提取来源证据。
