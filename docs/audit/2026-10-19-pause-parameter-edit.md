# 暂停中无法修改参数：修复与验收

## 根因

用户截图的任务状态为 `pausing`（暂停请求已接受，但在途请求尚未退出）。此前有两层按钮锁：

1. `workflow_view.js` 的 `taskBusy()` 同时禁用直接重跑和打开参数编辑。
2. `result.html` 的 `renderQueue()` 每次轮询又批量覆盖 `.wv-node-retry,.wv-node-edit` 的禁用状态。

真实浏览器验收复现第二层覆盖：参数组件已经允许编辑，但下一次详情刷新又将按钮锁回。两处均已修复。

## 实现与效果

- **允许先编辑**：任务处于暂停中时可以打开各步骤参数对话框；运行、排队、取消中的直接编辑限制保留。
- **安全应用**：参数输入保留在对话框，保存按钮在任务安全暂停前保持禁用。只轮询本地任务详情，不查询收费模型。
- **自动恢复保存**：任务变为已暂停后，保存按钮恢复；不清空用户已经填写的值。
- **防止旧窗口写入**：保存前再次读取同一任务状态；被别处重新启动、排队或状态查询失败时，不上传文件、不写配置、不入队重跑。
- **退出清理**：关闭对话框后清理轮询；迟到的响应不会重新启用已关闭的窗口。
- **草稿继续规则保留**：步骤6根据最新任务详情决定是否走已有 `/confirm` 断点继续，避免在暂停中打开窗口后仍误用旧的重跑分支。
- **单一按钮归属**：详情页不再在组件渲染后批量改写步骤按钮状态。直接重跑在暂停中仍然禁止，后端原有任务锁保留。
