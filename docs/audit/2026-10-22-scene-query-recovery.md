# 单张缺图无法查询原任务：恢复入口修复

## 根因与真实任务状态

用户截图10镜已有9张，本地第9镜有魔搭原任务编号，回执为pending、无结果地址。旧`scene_image_recovery.retry`只接受failed/rejected，不查询pending；整个任务queued时原通用任务锁又阻止单张操作。后台结果和本地状态脱节后，用户既看不到查询入口，也不能明确重试。

本轮通过现有软件模块只查询该原编号，无新增生成请求：首次返回SUCCESS与一个结果，随后复查返回FAILED且无结果。没有将首次查询的临时成功等同于已取回原图，也没有将本地pending擅自改成完成。尝试恢复在下载/写盘之前停止；真实第9张仍待恢复。供应商为何返回变化状态未确定，不作推断。

## 修复

- 同一鉴权接口支持严格布尔`query_only`：只查原任务/下载原结果，不调用生成器。查询原账户依旧核对凭据指纹，不更换账号。
- 查询SUCCESS先持久化原图片地址再下载；失败下载可按保存地址再取，不必再次轮询或购买；FAILED同步回执，才允许后续明确补图。
- 查询租约允许queued任务查回原图，同时占用该任务的实际操作锁，阻止同一任务worker并发开始；结束后解除租约、唤醒原队列，不改排队顺序和状态。运行/暂停收尾/取消中的任务仍保护。
- 图片按缺失编号写入，已有图片优先，原子硬链接落盘不覆盖同时到达的图片。原任务ID和成功图片保留。
- 缺图按钮改为「查图 / 补第N镜」，先只查询。明确失败且任务未在排队时，经费用确认才走原单镜重画；queued任务不旁路另购。
