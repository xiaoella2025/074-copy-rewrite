# Story 逐镜出图显示与 074 单条任务切换修复

## 依据

仅静态读取已拆解的 Story 1.25.0 活跃资源，没有运行安装包、Story 或其授权逻辑：

- `index-BjfyS2m-.js` 的出图 worker 逐镜发送 `image_started`、`image_ready`、`image_failed`。
- `Task-gC6tQ0el.js` 用 active-index Set 标记正在生成的镜号，在对应卡片显示转圈；完成后移除并立即显示图片。
- 任务详情提供“立即开始”“暂停修改”“继续任务”；审核暂停仍需查看并确认。
- 活跃 `Queue-DhSoN694.js` 没有“优先执行”按钮。因此 074 的调序按钮是此前已批准的本地功能，不能声称原样复制自 Story。

具体定位片段保存在本机私有验收目录 `story-evidence.json`，不将整个第三方 bundle 纳入 Git。

## 本轮功能、用途与实现

| 项目 | 实现 | 使用效果 |
| --- | --- | --- |
| 同时看到多张图在生成 | 用 `image_generation_progress.run` 包住既有线程池 worker，按任务路径与镜号记录开始/结束；任务详情只返回镜号数组 | 两个 worker 生成时，两张现有卡片分别转圈；完成一张立即显示图片，无需等整个批次结束 |
| 生成状态不覆盖成功图片 | 画廊先使用现有非空图片，再为缺图卡读取活跃镜号；worker 的 finally 清除状态 | 失败、暂停或请求异常后不会永久转圈；已有图片不会被状态占位替换 |
| 修正优先执行被旧暂停挡住 | 优先项移至队首时，将旧手动暂停项暂缓；明确优先执行其他项时，也可暂缓原失败拦截，但保留失败状态和原因 | 后面的任务真正具备调度资格；前面的产物与断点仍保留 |
| 单条开始、暂停、继续 | 复用已有 enqueue 接口，补列表“立即开始／暂停修改／继续任务／从断点续跑”；审核项显示“查看并确认” | 不必只依赖详情页控制单条任务；不会自动批准审核，暂停／定时批次仍需先在批次栏继续 |
| 暂停时停止长时间等待出图 | RunningHub、ModelScope 在已保存供应商任务 ID 后，每轮轮询检查队列 checkpoint | 停止等待原图并让调度继续；已提交任务仍留在供应商，不能宣称取消了平台计费 |
| 暂停后的图真正续跑 | pending receipt 记录 `poll_interrupted`；继续时对同一个 ID 有界轮询，逐轮检查暂停 | 避免“继续后只查一次、平台仍 RUNNING 就立即失败”，不重新提交生成任务 |

没有新增百分比、耗时面板或下载阶段显示，也没有改并发设置、收费重试策略、图片内容与队列审核规则。同步生成接口尚未返回时仍需等结果保存；正在进行的一次网络请求也需返回后才能检查暂停，不承诺瞬间切换。

## 验收

- 候选安装文件：77 项 Python、30 项 Node 测试通过。
- 真实图文出图处理器 + 本地 fake 供应商：两路同时活跃、第三路等待、单张先完成立即可读。
- 暂停已提交任务 → 选中的后续任务执行 → 继续原 ID，RUNNING → SUCCESS；新提交被测试禁止。
- 原图、原 receipt、未确认审核、定时批次、失败原因保留。
- 浏览器实际点击列表暂停、继续、优先执行，刷新后顺序保留；实际详情显示两张转圈，随后一图完成另一图继续转圈，刷新仍正确。
- Tabbit 截图接口超时，未取得截图；界面结果由真实 DOM、可见面板与布局边界核验，未伪称有截图验收。
