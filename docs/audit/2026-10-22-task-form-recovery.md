# 新建任务参考图预检与表单恢复

## 现场原因

用户选择 AI 绘图、内页魔搭并上传产品参考图，启动时报“产品参考图需要选择 AI 绘图，并使用全能绘图或支持图片编辑的自定义平台”。这不是模型调用失败，也不是新建入口不能点击，而是在生成请求发出前被兼容检查拒绝。

当前 `server.image_dispatcher` 的魔搭分支没有参考图编辑入口；批量生图端点也拒绝该组合。没有改成忽略图片后继续收费生图。该检查在 `index.html` 的既有 Git 记录为 `8f5062ed`（2026-10-02），不是10月19日模型跟随修复新增。安装文件清单仍与10月19日更新一致；无法据此识别任何其他操作人员。

## 修复、用途和效果

1. **兼容性提示提前。** 选择参考图或切换引擎后，在原表单明确显示冲突的是内页魔搭接入方式，说明封面引擎独立。启动兼容检查完成前不再切到运行页面，用户可以直接修改原设置。
2. **参数自动保存。** 编辑后防抖保存，点击开始前再保存一次。使用已有草稿结构及桌面原有的界面状态持久化链路，重新打开普通新建页会等待设置、模板初始化后恢复文案、商品、镜头数、风格、比例、引擎、音色和音乐选择。
3. **附件缓存。** 参考图、本地封面和上传配音保存在本机浏览器IndexedDB，不发送给供应商。附件与完整表单内容和唯一文件标识绑定；更换或移除文件后旧缓存不能重新匹配。写入失败时明确提示核对附件，不恢复旧图片。
4. **恢复顺序保护。** 先恢复模板默认值，再恢复用户手选比例，避免竖屏模板覆盖手选16:9。恢复过程不会触发默认值自动保存；初始化期间已开始输入时，不用旧草稿覆盖用户输入。任务续跑和显式转入页不会被普通新建草稿覆盖。

### 当前页面边界

仅静态页面更新，不关闭应用、不刷新用户当前页面。已经加载的旧脚本不会自动获得新保存逻辑，因此用户首次刷新前需用已有“保存为草稿”保存当前表单；旧页面未缓存的附件需重选一次。新页面的附件缓存属于当前本机浏览器来源，来源变化、缓存被清除或存储失败时提示重新核对附件。
