## 功能如何实现

| 功能 | 实现方法 | 用户使用方式 |
|---|---|---|
| 识别不覆盖手改稿 | 本地 ASR 下载/识别前记录原文和纠错稿；写回前在原有锁内重新核对。改稿或删除即拒绝写回，互动指标更新不影响保存 | 原入口继续使用；发生冲突会说明保留了手改稿 |
| 关页后继续批量 | 原按钮提交固定作品身份清单，后台线程执行；每条领取与结果写入独立原子 JSON，保存失败立即停住 | 仍使用作品列表原有批量按钮，可切页或刷新 |
| 可见真实进度 | 页面沿用既有轮询读取批次，显示 n/N、成功/失败/待确认；筛选为空也保留进度 | 批量栏查看状态，逐项详情默认折叠，展开状态在轮询后保留 |
| 中断后显式继续 | 软件重新读取 running/queued/stopping 时转为 interrupted，不启动工作线程；继续只处理 pending/failed | 点击“继续未完成项”，已成功和待确认项跳过 |
| 收费请求去重 | 重交同请求 ID 返回原批次，不同内容拒绝；带货判定复用已有 SQLite 回执，旧标题/文案指纹变化时不发新请求 | 提交丢响应可重试同一批次；未确认的收费项需核对供应商记录 |
| 导出入口完整 | 后台只生成既有文案导出文件并保存引用，不自动弹窗；用户点击下载或显示位置 | 展开“查看逐项结果”，选择单条下载/位置入口 |

新增接口沿用桌面会话及 Origin 验证；限制 1–100 条、128 KiB 请求体，拒绝重复作品和路径式批次编号。备份恢复不读写批次目录或收费回执，不会触发续跑。
