# RH 币生图独立试用入口

日期：2026-10-25。状态：用户已确认，开发与隔离验收完成；尚未安装或实跑。

## 用户已明确的目标

074 新增一个单独试用的 RH 币生图入口；现有三种模式、G2 和其他生图配置保留。不要求用户自己找工作流，由我们筛选。先单张试验，效果不合适可以关闭，不接进旧任务自动流水线。

## 推荐的实现方式

复用现有 `modelscope_reference_experiment.py` 独立实验的结构，建立单独页面、配置和任务目录。导航提供“RH币生图 · 实验”入口，默认关闭。界面只需配置消费级会员 Key、查看工作流、填写画面描述、选择比例、生成一张、查询原任务、预览和另存图片。

不把新通道直接塞入系统现有绘图引擎选择：用户明确要求单独试用，这样可以在画质和计费验收后再决定是否用于正式任务。

## 工作流选择

优先审查 Qwen 原生文生图候选，候选链接与证据记录在 `docs/audit/2026-10-25-runninghub-manual-and-coins.md`。由实现者取得完整 API 图，确认开源推理、单图输出和必要节点；通过后保存固定图和摘要，不让用户手填节点 ID。不因标题包含“Qwen”就认定只扣 RH 币。

第一版不支持任意第三方工作流执行；未经核对、隐藏/加密节点、闭源 API 节点不能进入生成状态。账户地区与 Key、工作流一致，未经选择不切换域名。网页先跑通的要求以真实单张验收确认，不能拿离线测试代替。

## 配置和界面行为

- 独立保存会员 Key；接口只返回是否已配置，页面不显示原始 Key，不覆盖 G2 Key。
- 开关默认关闭。关闭只阻止新提交，已存在任务仍可查询、取回和保存结果。
- 配置核对只读账户和工作流资料；按钮明确写“核对配置，不生成”。账户余额显示 RH 币和钱包分别列出，不凭余额猜成本。
- 提交按钮明确写“生成1张（消耗RH币）”；只执行一次，不批量遍历风格，不自动调用钱包模型兜底。
- 计费说明按平台实际运行时间计费；运行前不虚构固定每张价。验收后用平台账单确认实际币种与消耗。
- 下载要使用已有本地文件保存机制，保存成功给出实际路径；不只依赖桌面 WebView 的 `download` 属性。

## 提交与恢复

提交前持久保存 operation ID、提示词、尺寸、固定工作流摘要和状态；同 operation ID 重复点击返回原记录，不再购买。收到平台 taskId 立刻落盘，然后轮询原任务。

状态包括待提交、提交中、排队、运行中、取回中、成功、平台确认失败、提交状态不明。网络断开/没有 taskId 属于不明，不能当作确定失败自动重发；页面提供核对原记录的提示。取图失败继续下载原结果，不重新生成。平台明确失败才允许用户另开一次新生成。

新目录与生产 tasks 分离，原文、已成功分镜、封面和队列不受影响；不自动重新生成旧任务。

## 验收与完成边界

1. 离线：模拟接口验证默认关闭、配置隔离、正确路径/字段、未知节点拒绝、单图约束、重复点击、断网恢复、关页重开、结果取回和真实文件另存。
2. 候选安装版：使用临时业务目录和模拟平台验证真实后端入口与浏览器界面；不调用真实供应商。
3. 安装：保留已有独立修复，核对运行清单与业务文件哈希；仅在用户正常关闭 074 后替换后端。
4. 实际接通：另经用户明确同意，仅运行一张并核对 RH 任务账单。未实跑前标明“待实跑验证”，不宣称工作流已可用或已确认只扣币。
